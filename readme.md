# longtail (pure Rust)

A pure-Rust implementation of [longtail](https://github.com/DanEngelbrecht/longtail) and the
parts of [golongtail](https://github.com/DanEngelbrecht/golongtail) we use. It is byte-compatible
with the C library's on-disk formats — `.lvi` version indexes, `.lsi` store indexes, and `.lsb`
stored blocks — and with existing S3 and local-filesystem stores, and it ships a
golongtail-compatible CLI. The longtail C library is neither built nor linked — "pure Rust"
means the longtail implementation itself, not the whole dependency tree: a normal build still
compiles the C in `zstd-sys`, `blake3`'s SIMD paths, and (with the default `s3` feature)
`aws-lc-sys`.

## Crates

- **`longtail-core`** — the on-disk format codecs and algorithms (chunker, hashing, compression,
  store-index algebra, version build/diff). Sync, no async runtime.
- **`longtail-store`** — blob and block stores (filesystem, in-memory, S3), the remote-store actor,
  caching/compression decorators, and optimistic store-index sync. tokio-native.
- **`longtail`** — the facade: `downsync`/`upsync` operations, error tree, progress, cancellation.
- **`longtail-cli`** — the command-line tool (`get`, `downsync`, `upsync`, `put`, `ls`,
  `print-version`, `validate-version`, `prune-store`, `clone-store`, `cp`, …).

`longtail-sys` and `longtail-ffi` under `support/` are **legacy** — bindings to the C library kept
only for differential regression testing, not part of a normal build.

## Quick start

**CLI** — resolve a get-config JSON (it names the store and version) into a directory:

```sh
cargo run -p longtail-cli -- get \
    --source-path s3://my-bucket/store/versions/v1.json \
    --target-path ./out
```

or the lower-level form, pointing straight at a version index:

```sh
cargo run -p longtail-cli -- downsync \
    --storage-uri s3://my-bucket/store \
    --source-path s3://my-bucket/store/index/v1.lvi \
    --target-path ./out \
    --cache-path ./cache
```

**Library** — the facade is a plain `async fn` on your own runtime, with credentials injected as a
provider/client (so they refresh mid-transfer):

```rust
use longtail::{downsync, DownsyncOptions};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // source version index(es), storage URI, target folder
    let mut opts = DownsyncOptions::new(
        vec!["s3://my-bucket/store/index/v1.lvi".into()],
        "s3://my-bucket/store",
        "./out",
    );
    opts.cache_path = Some("./cache".into());
    // ...plus worker counts, injected S3 credentials/client, progress, cancellation.
    let _stats = downsync(opts).await?;
    Ok(())
}
```

## Compatibility

100% byte-compatibility with existing longtail data stores is the paramount guarantee, verified by
committed golden fixtures (generated by a pinned upstream CLI) and by differential tests against
the C library in both directions.
